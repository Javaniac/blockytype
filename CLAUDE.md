# BlockyType

Typing-test game played inside Minecraft: Java Edition. Inspired by Monkeytype: players type a given text, and the server measures WPM, CPM and accuracy. Runs as a Minestom server written in Kotlin. Licensed GPL-3.0 (matches Monkeytype, so its word lists and code can be reused with attribution).

BlockyType has its own visual identity. Borrow mechanics, metric definitions and word data from Monkeytype, not its UI layout, branding or theme set.

## Stack
- Kotlin 2.4 on JVM 25 (`jvmToolchain(25)`), Gradle Kotlin DSL. The jar is slim (about 1 MB): a Java bootstrap downloads every runtime library (Kotlin included) on the first start.
- Minestom `2026.10.07-26.2` (version suffix = target Minecraft version: 26.2, protocol 776, resource pack format 88).
- kotlinx-coroutines, Adventure MiniMessage, Exposed + SQLite (persistence), Logback (`logback.xml`: `yyyy-MM-dd HH:mm:ss LEVEL Class message`, colored, one logger per class via `LoggerFactory.getLogger("Name")`).

Its `net.minestom.server.Git.commit()` is `23ee1171302c06794877a5f91be1d0d5c2d4619e` (`refs/pull/3369/merge`).
  - List builds: `.../net/minestom/minestom/26_3-SNAPSHOT/maven-metadata.xml`.

## Commands
- Build jar: `./gradlew jar` (output `build/libs/blockytype-1.0-SNAPSHOT.jar`, only BlockyType classes, JetBrains Mono, `languages/index.txt`, `libraries.txt`). `generateLibraries` writes `libraries.txt` (every runtime library with its SHA-256) from `runtimeClasspath`. `./gradlew soundsZip` builds `build/assets-release/sounds.zip` from `assets/sounds` and prints its SHA-256 (pin it in `SoundDownloader`, upload the zip as a release asset). `./gradlew verifyBuiltinFonts` (internet) downloads all built-in fonts and runs the font check; it is not part of `test`.
- Run: `java -jar build/libs/blockytype-1.0-SNAPSHOT.jar` (binds `0.0.0.0:25565`, online-mode auth). First start downloads (internet needed): libraries into `libraries/` (`bootstrap/Bootstrap.java`: JDK only, Maven Central, SHA-256 checked, one `URLClassLoader` with the jar itself, parent = platform loader, context loader set), the english word list into `languages/` (`LanguageDownloader.ensureDefault`), the sounds into `sounds/` (`SoundDownloader`) and the 21 built-in fonts into `fonts/builtin/` (`FontInstaller`, in the background after the server started, then the packs are reloaded). A failed sound download is only a warning (no sound).
- Resource pack: generated by the server itself (`pack/PackBuilder`) at startup, in memory, and hosted over HTTP on port **25500** (`PackServerConfig`, `http://localhost:25500/pack.zip`; host/port will become configurable together with the game server ip/port). Edit `PackBuilder.kt` / `Shaders.kt`, not generated files.
- Server commands (console reads stdin via `Console.kt`, or players listed in `admins`): `pack reload` (also re-reads `blockytype.properties`), `pack font list|download <url> [name]|use <name>|reset`.
- Config: ONE text file `blockytype.properties` in the working dir (`settings/SettingsFile`, specs in `settings/ServerSettingSpecs`): `server-ip`, `server-port`, `resource-pack-ip`, `resource-pack-port` (network, apply at the next start; the server takes no startup arguments), and the server defaults `font`, `input-box`, `animation`, `anti-aliasing`, `theme`. Every option has `#` comment lines above it. The server rewrites only the value of one line (admin panel, `pack ...`), so comments, unknown lines and order are kept; missing options are added with their comment (self-documenting after upgrades); hand edits are read by `pack reload`. Old files: `show-input` becomes `input-box`; rows of the old `server_settings` table are copied into the file once and then deleted. The admin list stays in the database (`/grantadmin`, `/revokeadmin` in the console). Players on the server machine get the pack URL with `127.0.0.1` (`PackServerConfig.url`), so a public `resource-pack-ip` without hairpin NAT does not lock the host out.
- Fonts (`pack/FontRegistry`, `FontInstaller`, `FontManifest`): the jar holds only JetBrains Mono (+ license). `fonts/builtin/` = JetBrains Mono plus the 21 downloaded built-in fonts (pinned raw GitHub URLs + SHA-256 in `FontManifest`, each with its license `<name>.license.txt`; the pack carries the active font's license as `licenses/<name>.txt`), `fonts/custom/` = the admin's own `.ttf`/`.otf` (optional `<name>.license.txt`), `fonts/README.txt` explains it. At startup `FontRegistry.init()` moves unknown files from `builtin/` to `custom/` with a WARN and validates every font; `names()` (settings list, menu, suggestions, `pack font list`) and `load()` only accept fonts that pass `FontInfo.load` (monospace, and strokes >= 0.05 em: a variable font whose default instance is Thin vanishes in the anti-aliasing filter; azeret-mono used to). Invalid fonts are skipped with a WARN (results cached by mtime/size). `pack font download <url>` saves to `custom/`. A font change by `pack font use` is saved in the settings file and reloads the pack. Test fixtures: `src/test/resources/fonts` (generated, monospace/proportional/thin).
- Data: SQLite file `blockytype.db` in the working dir (Exposed): `test_results` (one row per finished test) and `player_settings` (theme, add columns for new settings).
- Tests: `./gradlew test` (JUnit 5 via `kotlin("test")`, Minestom is a test dependency too). They cover the typing engine, stats and HUD title building. The real client is tested by driving the game (see "Testing in the client").
- Windows: `./gradlew` needs `JAVA_HOME` (e.g. `~/.jdks/graalvm-jdk-25*`).

## Layout (`src/main/kotlin/com/javaniac/blockytype/`)
- `BlockyType.kt` – entry point; `object BlockyType` is the app-wide `CoroutineScope`; registers listeners and themes.
- `Extensions.kt` – MiniMessage helpers (`String.toComponent()`, `Component.toMiniMessage()`), `Int.ticks`, `withMinestomMain` / `withMinestomMainResult` to hop from coroutines back to the Minestom tick thread.
- `events/` – one `object : EventListener<T>` per event; register in `BlockyType.main`.
- `themes/` – `AbstractTheme` interface (color roles: bg, main, caret, sub, subAlt, text, error); defaults = default theme.
- `ServerConfig.kt` (admin set), `settings/ServerSettings` + `SettingsFile` (the settings file), `Console.kt` (stdin console; Minestom has none).
- `pack/` – `PackBuilder` (pack as path-to-bytes map + zip), `Shaders` (core shader templates per client version), `PngWriter`, `Json`, `PackServer` (HTTP host + resource pack request + `reload()`), `FontInfo` / `FontRegistry` / `FontDownloader` (font choice, scaled so one char advances exactly 6 GU).
- `ui/` – `UiFont` (advances, space glyphs, color marker), `TitleBuilder` (zero-width segments, `Element` ids), `HudState`, `HudRenderer` (one boss bar per player), `ResultGraph` (dot-glyph geometry).
- `words/` – Monkeytype word lists: `LanguageRegistry` (index, order: `english`, other `english_*`, rest alphabetical), `LanguageDownloader` (big lists on demand), `WordGenerator` (Monkeytype `getNextWord` rules, optional Zipf), `JsonReader`.
- `game/` – `TestFactory` (settings to test), `TargetText` (word wrap, appendable), `TypingTest` (Monkeytype word semantics), `TestStats` (wpm/raw/acc/consistency), `TestSession` (per player: test, screen state, command block, timer), `TypingCommandTree` (the custom command tree), `ResultView`.
- `events/` – `join/ConnectEvent` (instance, command block, creative + op 2), `join/JoinEvent` (camera stand, session), `game/GameEvents` (right-click, suggestion packets, F, protection).
- `db/Database.kt` – `Storage` (Exposed/SQLite): `saveResult`, `bestWpm`, `loadSettings`, `saveSettings`.
- `commands/PackCommand.kt` – the `pack` command.

### Typing flow (verified in game, 26.3 client)
- The player body hovers (creative flying, moves cancelled) **behind** the camera stand: the ray from the stand must not start inside the player's body (that made the crosshair hit the player entity). Marker stands have **no eye height**: the stand's y is the eye y (1.5), the command block is at y 1.
- Right-click on the block: the client opens the screen and sends an empty suggestion request *before* the interact packet. The server then prefills `/t ` + the accepted text (`BlockEntityDataPacket`).
- Command tree: one root-level greedy string argument with `ask_server` (`TypingCommandTree`). Unlike a `/t <text>` command, the client then sends a request for **every** edit including `/t`, `/`, `""`. Text up to the cursor, with the leading `/`.
- Text not starting with `/t ` cancels the test (reset + the screen is closed by removing the block for 3 ticks, which makes the client close its screen). An empty text only cancels if no right-click follows within 2 ticks (a reopen after Esc looks the same).
- Esc is invisible to the server: the test is kept, the next right-click resumes. Enter/Done is ignored. Chat typed while the server still thinks the screen is open cancels the test (known limitation).
- Only a single appended char or a deleted tail is accepted (paste is rejected and the box is resynced). Correct committed words are locked against backspace.
- F (`PlayerSwapItemEvent`) restarts; a finished test shows the result HUD and closes the screen.
- Driving the real game: `Client.connect("localhost", 25565)` and `KeyBind.pressKeyBind("key.use")` through the Minecraft MCP. Typed chars: call `screen.charTyped(new CharacterEvent(cp))` on the main thread; backspace: reflect the `commandEdit` field and call `deleteChars(-1)` (key events do not reach the box). Mojang rejects joins within about a minute of each other (HTTP 429).

### Keybind hints and probe (verified in game, 26.3)
- Q (drop) opens the settings page, Ctrl+Q (`DROP_ITEM_STACK`) opens the admin panel (admins only, checked server-side in `MenuInput.dropAction`). The typing screen shows them in the top right corner (element ids 29, 30, right aligned to the screen edge, `Keybinds.side`); with F3 open the debug overlay covers them.
- `KeybindProbe`: 3 s after join an anvil opens holding an item named by keybind components (`key.drop`, `key.swapOffhand`, `key.use`, separated by `Keybinds.SEP`). The client resolves them with its own bindings and answers with a `ClientNameItemPacket`; `Keybinds.parse` validates it (client text) and the footer/side hints use the player's real key names. Gives up after 5 s and keeps the defaults.

### Invisible probe anvil, F1 notice, chat completions (verified in game, 26.3)
- The `KeybindProbe` anvil is invisible: the pack has transparent `textures/gui/container/anvil.png`, `container/anvil/*` and `slot_highlight_*` sprites; the probe item uses `item_model` `blockytype:blank` (`items/blank.json`, model type `minecraft:empty`) and a hidden tooltip; `text.vsh` makes every unmarked text transparent while `Globals.GameTime < Shaders.PROBE_GAME_TIME` (-0.25); the server sets the client game time to `Stopwatch.PROBE_TICKS` (-12000, a negative time a real world never has) before opening the anvil and back to 0 when the probe ends; `gui.vsh` hides the white insert cursor of the name box (anvil layout: 176 x 166 centered, box at 62,24, 103 x 12).
- F1 (hide GUI, `key.hideGui` in 26.3; `Hud.isHidden`) shows the world behind the boss bar HUD: `HiddenHudNotice` spawns a big text display (30 lines of "You have hidden the HUD. Press F1 to show it again", theme bg and main colors, full brightness, billboard) 0.9 blocks in front of the camera stand, between it and the command block. Only that player sees it. The HUD background covers it otherwise.
- Chat completion for `/` offers only `settings` (`TypingCommandTree` has the `t` argument and the `settings` literal; `restart` and `pack` still work but are not advertised). Every chat suggestion request gets an answer (`CommandSuggest.answer`, empty when there is nothing): the client waits for every `ask_server` node before it shows the list. Commands of the player's own client mods (e.g. `/chattools`) also show up, that is client side.

### Menus (verified in game, 26.3)
- Q opens the settings page (`MenuSession`, `ui/MenuLayout`), Ctrl+Q the admin tab. There is no quick menu: options are also changed in chat with `/settings <setting> [value]` (`SettingsChat`; `default` follows the server default, `/settings reset` clears all, `/settings` alone opens the page) and `/restart`. The client only knows the typing command tree, so chat shows no suggestions for them. In a menu the camera moves to the player (`CameraPacket(player.entityId)`), because the client only sends movement keys when it controls the camera (with the stand camera no `ClientInputPacket` and no rotation arrive). The command block is removed so a right-click cannot open its screen.
- There is **no mouse cursor**. Input: wheel or number key (`PlayerChangeHeldSlotEvent`, cancelled, direction only) and W/S move the focus between rows, A/D between the options of a row, left click (`PlayerHandAnimationEvent`) or space (`ClientInputPacket.jump`, edge detected by `MenuInput.navPresses`) selects. A held W/A/S/D repeats (`KeyRepeater`: 350 ms delay, then every 100 ms, driven by a 1 tick task because the client only sends key changes; space never repeats). Head turns are ignored (the cancelled `PlayerMoveEvent` resyncs the body).
- Footer: the description of the focused setting is longer than one line (50 chars), so it scrolls (`Marquee`: rests 8 steps, then one char per 140 ms, rests at the end, repeats; `MenuSession.tick` is called by the 1 tick menu task and only redraws when the window moved; a new focus restarts it).
- Chat replies of `/settings` (`SettingsChat`) are Adventure components colored with the player's theme (caret `»` prefix, main = value, sub = labels/other choices, error = problems); the theme is read after the change; choices are click-to-run. The result screen footer uses the detected keys (`ResultView.toHudState(.., keybinds)`).
- Look (Monkeytype settings page): section tabs on a sub-alt strip, big section title (`mono_big`), per setting the title on the left and option pills on the right (active pill = main fill with bg text, others sub-alt fill), description of the focused setting in the footer, focused cell = tall outline block. Pills, strips and outlines are drawn with `ui` block glyphs (`UiFont.block(width, tall)`: glyph `BLOCK_BASE`/`TALL_BASE` + k is 2^k wide, each followed by a -1 space), drawn before the text in the same element so the text covers them (`TitleBuilder.placed`).
- Element ids: 16 header, 17..28 body rows (pitch 15, first at cy-88), 31 footer, 29/30 keybind hints of the typing screen.
- Typing a value (admin network settings): selecting the value (`edit:<key>`) calls `TestSession.beginEdit`, which puts the command block back; the player right-clicks it like in a test. Every box edit (`/t <text>`) updates the draft (`FieldEdit`, shown live in the pill), Enter/Done (`ClientUpdateCommandBlockPacket`) validates (`NetworkSettings.validate`) and saves to `blockytype.properties` (applies at the next start), Q cancels. All checked again server side (`isAdmin`, known key).
- Testing a build without touching a running server: `./gradlew --init-script <file> shadowJar` with an init script that sets `shadowJar.destinationDirectory` to `build/test-libs`, copy the jar to a scratch dir and run it there with a `blockytype.properties` there setting `server-port=25575`, `resource-pack-port=25501`, `resource-pack-ip=localhost` (own `blockytype.db`; an admin can be seeded into `admins` with sqlite). Join it with `new ServerData("bt-test", "localhost:25575", ServerData.Type.OTHER)` + `setResourcePackStatus(ENABLED)`. The raw screen is `Hud.getOpenScreen()` (`mc.screen` reads as null in JsMacros); set the command box with the `commandEdit` field's `setValue`, press Done by invoking `onDone`. Keys: `KeyBind.pressKeyBind("key.forward"|"key.back"|"key.left"|"key.right"|"key.jump"|"key.drop")`.

Prototype helpers written while researching. They are **not part of the project**. `build_pack.py` and `hud_proto.py` were ported to `pack/` and `ui/`, verified in game, and deleted.
- `mc.ps1` drives the running Minecraft window for in-game tests. Prefer the Minecraft MCP (see "Typing flow" and "Testing in the client"). It's a dev tool, not game code. Delete it once it is no longer needed.

- **Resource pack contents** (generated at runtime by `pack/`, no checked-in files). `pack.mcmeta` covers formats `[88,0]`–`97`, with overlay `overlay_26_3` for 97. The zip has `pack.mcmeta` at its root. Contents:
  - Command block screen hiding:
    - `widget/text_field*` sprites are transparent.
    - `advMode.*` labels are blanked in `en_us` only.
    - Own flat `widget/button*` sprites (marker alpha 254).
    - `core/text.vsh`, `core/gui.vsh` and `core/position_tex_color.vsh/.fsh` match by color + GUI position.
  - HUD:
    - Transparent `boss_bar/*` sprites.
    - Fonts `blockytype:mono`, `mono_big` and `ui`, with bitmaps in `assets/blockytype/textures/font/`.
    - The HUD layout code in `core/text.vsh`.
  - `licenses/JetBrainsMono-OFL.txt`. It sits outside `assets/` because asset paths must be lowercase; an uppercase name logs "Invalid path in pack".
  - Hiding rules:
    - The command box text is **not** only `0xE0E0E0`. `CommandSuggestions` syntax-highlights it with `GRAY` literals, `AQUA`/`YELLOW`/`GREEN`/`LIGHT_PURPLE`/`GOLD` arguments and `RED` for unparsed text. All of those plus their ×0.25 shadows are hidden inside the box rectangle.
    - Button sprites (`widget/button*`) are BlockyType's own flat art with **alpha 254 as a marker**. `position_tex_color.fsh` discards marker texels only inside the command block button rectangles. Button labels (white / `0xA0A0A0`) are hidden in `text.vsh` in the same rectangles.
    - Side effect: every in-game screen loses its dim background (accepted).
    - Usage hint: `CommandSuggestions.extractUsage` draws the hint (e.g. `<text>`) as one `GRAY` (`0xAAAAAA`) line at y ≈ 74, on a `0x80000000` fill. It starts at the argument column and is only produced for non-literal nodes. It is hidden only at y 72–86, left of dx −40, so **keep the `/t` argument name short** (≤ ~8 chars). The suggestion list is not hidden; the server never returns suggestions, so it never appears.
    - Done / Cancel / O-X labels are hidden only in label-sized rectangles around their centered text, not in whole button rows. Wide rules here broke every menu's button labels.
    - **Color rule for BlockyType UI text:** inside these rectangles, never emit the hidden colors exactly (`0xFFFFFF`, `0xE0E0E0`, `0xA0A0A0`, `0xAAAAAA`, `0x808080`, the `CommandSuggestions` syntax colors). Nudge a channel by 1 instead, e.g. `0xFEFEFE`.
  - Shader syntax differs per client version. Base `assets/` = 26.2 (format 88: `#moj_import`, no layout qualifiers). `overlay_26_3/` = 26.3 (format 97, "renderpearl" renderer: shaders compiled to SPIR-V, `#include <minecraft:x.glsl>`, `#extension GL_ARB_separate_shader_objects : require`, every `in`/`out` needs `layout(location = N)`, and `DynamicTransforms` member order is `ModelViewMat, TextureMat, ColorModulator, ModelOffset`). Always start an override from that version's vanilla file. A shader error makes the client drop the whole pack.

## Conventions
- Event listeners are Kotlin `object`s implementing `EventListener<T>`.
- Touch Minestom entities/players only on the tick thread; from coroutines use `withMinestomMain`.
- Build chat/UI text with MiniMessage strings via the helpers in `Extensions.kt`.
- Kotlin official code style (`gradle.properties`).

## Game design (target)
1. Player joins a void instance; camera locked to a marker armor stand.
2. Player right-clicks the command block placed in front of the camera, which opens the screen (see "Client behaviour"). F (`PlayerSwapItemEvent`) restarts or resets the test.
3. A command block edit screen opens. The server prefills it with `/t `, and the resource pack hides the vanilla screen.
4. Each keystroke makes the client send a command-suggestion request with the current text. The server reads it, diffs against the target text, and updates progress, mistakes and live metrics.
5. Game UI renders through a server resource pack with core shaders, not text displays.
6. On finish: result screen on the HUD (wpm, acc, raw, characters, consistency, time) with a wpm/raw-over-time graph. No chat output.
- Command block screen chosen because its input limit is higher than chat and it can be hidden.
- Metrics: follow Monkeytype definitions (WPM = correct chars / 5 / minutes) – see `frontend/src/ts/test/test-stats.ts` in Monkeytype source.
- Themes: palettes map to `AbstractTheme` color roles; user-selectable.
- Future: multiplayer races.

## Client behaviour (verified in decompiled client 26.3 via mcsrc.dev; project targets 26.2, re-check if behaviour seems off)

Opening the command block screen:
- No server packet opens it. The client opens `CommandBlockEditScreen` itself in `CommandBlock.useWithoutItem` when the player right-clicks a command block and `player.canUseGameMasterBlocks()` is true (creative + gamemaster permission, i.e. op level 2). `MinecartCommandBlock` works the same way through entity interaction.
- `MultiPlayerGameMode.performUseItemOn` returns early in spectator mode. So the client must believe it is in creative when it right-clicks. The fake spectator game state sent in `JoinEvent` blocks this.
- Swap Offhand (F) only sends `ServerboundPlayerActionPacket(SWAP_ITEM_WITH_OFFHAND)` when the client is not in spectator. It cannot open the screen. F can start or reset a test; opening the screen needs a right-click (use key) on a command block.
- The crosshair raycast starts from the camera entity (`Minecraft.pick` calls `player.raycastHitResult(partialTicks, cameraEntity)`). With the camera on the armor stand, a command block placed in front of the stand is what the player targets. Interaction range still applies.
- The screen opens with an empty text box and a disabled Done button. The server fills it by sending `ClientboundBlockEntityDataPacket` for that block with `Command: "/t "`. `ClientPacketListener.handleBlockEntityData` then calls `CommandBlockEditScreen.updateGui()`, which runs `commandEdit.setValue(...)`. Sending the packet again while the screen is open resets the text box (useful to restart a test).
- `AbstractCommandBlockEditScreen.tick()` closes the screen if the command block is no longer valid (block removed).

Reading keystrokes:
- The command box is an `EditBox` with `setMaxLength(32500)`. `CommandSuggestions` is built with `commandsOnly = true`.
- Every text change calls `CommandSuggestions.updateCommandInfo()`. It parses with the client-side command tree and calls `getCompletionSuggestions(parse, cursorPosition)`. An argument with `ask_server` suggestions makes `ClientSuggestionProvider.customSuggestion` send `ServerboundCommandSuggestionPacket(id, text)`. There is no throttling: one packet per edit. The previous pending request is cancelled client-side.
- The text sent is the input **up to the cursor** (includes the leading `/`). If the player moves the cursor left, the server only sees a prefix.
- The server needs to reply only when it wants suggestions. The client ignores replies whose id is not the latest.
- Packet text limit: 32500 in the client codec and in Minestom (`ClientTabCompletePacket.MAX_TEXT_LENGTH`).
- Minestom side: register `/t` with a greedy string argument and `setSuggestionCallback(...)`. That marks it `ASK_SERVER`. Requests go through `TabCompleteListener` (strips the leading `/`), or intercept `ClientTabCompletePacket` raw with `PlayerPacketEvent`.
- Enter (or Done) calls `onDone()` and sends `ServerboundSetCommandBlockPacket` with the full text (`ClientUpdateCommandBlockPacket` in Minestom). Escape closes the screen and sends nothing. The server cannot see the close directly; it can only notice that suggestion requests stopped.

Hiding the vanilla screen (resource pack):
- Text box background: sprites `widget/text_field` and `widget/text_field_highlighted` (shared with other text boxes such as chat).
- Typed text: `EditBox` default colour `0xE0E0E0` (`DEFAULT_TEXT_COLOR = -2039584`); read-only text `0xA0A0A0`. A core text shader can discard glyphs by exact colour.
- Labels (`advMode.setCommand`, `advMode.command`, `advMode.previousOutput`, `advMode.mode.*`, `advMode.trackOutput`) are translatable. Blank them with a lang override in the pack.
- Done and Cancel use the shared `gui.done` / `gui.cancel` keys and button sprites. Blanking those also affects every other screen, so prefer a shader-based approach or accept the side effect.
- Background: the command block screen is in-game UI (`isInGameUi() = true`). It does **not** blur. `Screen.extractTransparentBackground` draws `fillGradient(0, 0, w, h, 0xC0101010, 0xD0101010)` through pipeline `GUI` (core shader `gui`). A `gui.vsh` override can make vertices with those exact colors transparent.
- Suggestion/usage box drawn by `CommandSuggestions`: the server avoids it by never returning suggestions. A greedy string argument never produces parse errors.

## Rendering plan (game UI + graph)
Verified against the 26.2 client jar (`resource_major` pack format **88**, protocol 776). Mojang jars are unobfuscated, so `javap` and mcsrc names match.

Draw order:
- `Gui.extractRenderState` draws the HUD first (`Hud.extractRenderState`), then the open screen on top.
- So HUD elements (boss bars, title/subtitle, action bar) stay visible under the command block screen.
- Once the vanilla screen pieces are hidden, the HUD is the canvas.

Core shaders (`assets/minecraft/shaders/core/`, GLSL `#version 330`, `.vsh` / `.fsh`):
- All GUI text uses `text.vsh` / `text.fsh` with `IS_GUI` defined (pipeline `GUI_TEXT`). World text uses the same files without `IS_GUI`.
- Uniform blocks available: `Projection` (`ProjMat`), `DynamicTransforms` (`ModelViewMat`, `ColorModulator`, ...), `Globals` (`ScreenSize`, `GameTime`, `MenuBlurRadius`, ...).
- Includes: `#moj_import <minecraft:globals.glsl>` (26.2) / `#include <minecraft:globals.glsl>` (26.3).
- The `Globals` member order differs between versions:
  - 26.2: `CameraBlockPos, CameraOffset, ScreenSize, GlintAlpha, GameTime, MenuBlurRadius, UseRgss`.
  - 26.3: `CameraBlockPos, GlintAlpha, CameraOffset, GameTime, ScreenSize, MenuBlurRadius, UseRgss`.
  - Always use the include, never an inline copy.
- `gui.vsh` and `position_tex_color.vsh` carry the comment "Can't moj_import in things used during startup". Copy the uniform blocks inline when overriding them; `Shaders.dyn()` writes the per-version `DynamicTransforms` order.
- Overrides of `gui.vsh`, `position_tex_color.*` and `text.vsh` are verified to take effect in 26.3.
- GUI size inside shaders: `guiWidth = 2/ProjMat[0][0]`, `guiHeight = 2/abs(ProjMat[1][1])`. Round both; they are float-imprecise. GUI position = `(ModelViewMat * vec4(Position, 1)).xy`.

HUD technique (**prototype verified in the 26.3 client**, see `text.vsh` "BlockyType HUD"):
- **The whole game UI is the title of one boss bar.**
  - `BossHealthOverlay`: bar *i* at y = 12 + 19i, title at y − 9 (first title y = 3), title x = `guiWidth/2 − font.width/2`, base color white with shadow, bars stop at `guiHeight/3`.
  - Boss bar sprites (`boss_bar/*`) are transparent.
- `Hud` order: crosshair, hotbar, effects, **boss overlay (new stratum)**, scoreboard, action bar, title, chat, tab list. So a full-screen bg glyph in the title covers the world, crosshair and hotbar. Chat draws on top. F1 hides it all (accepted).
- **Zero-width title.**
  - Every element (segment) is followed by a negative space equal to its own advance, so the title's `font.width` is 0. The title origin is then exactly (`floor(guiWidth/2)`, 3), and every segment starts there.
  - Centering inside a segment: leading space `-w/2`, text, trailing space `-(w - w/2)`.
- **Marker** (vertex color low bits):
  - `R & 7 == 3` marks the vertex (plain marks also keep R bit 3 clear; the caret sets it). Element id = `(G & 3) << 2 | (B & 3)`.
  - No vanilla text color or shadow has `R & 7 == 3`. A plain `R & 3` marker collided with GRAY `0xAA` and moved the command box text.
  - The server snaps theme colors to marked values (≤ 4/255 off).
  - Only vertices at pre-transform |y| < 96 are moved.
  - **Never send marked colors outside the HUD title.**
- **No shadows:** every HUD component sets `shadow_color: 0`.
- **Layout follows the vanilla GUI scale (user choice).**
  - The shader adds segment-local coordinates to a per-element anchor computed from `guiWidth`/`guiHeight` (taken from `ProjMat`). No scaling.
  - No player input is needed: the server cannot learn the screen size or GUI scale (`ClientInformation` has neither).

## Monkeytype reference (research, site v26.43.0, source `master`)
**Adopted: everything in this section** (modes, metric formulas, invalid-result rules, settings, data formats), subject to the visual-identity rule at the top. BlockyType uses its own theme palettes, not Monkeytype's presets.

Result screen layout:
- Big `wpm` and `acc` on the left.
- A chart to the right:
  - x axis: seconds.
  - Left y axis: words per minute. Right y axis: errors.
  - Main-color line: `wpm` (cumulative). Sub-color smoothed line: raw (per-second burst). Faint dashed line: average.
  - Red `×` markers: seconds with errors.
- Bottom row: test type (e.g. `words 50` / `english`), `raw`, `characters` (`correct/incorrect/extra/missed`), `consistency`, `time` (plus session time).
- Example: wpm 110, acc 96%, raw 116, characters 263/4/1/0, consistency 74%, time 29s.
- BlockyType shows this on the HUD result screen at test end, with a graph of wpm (main color) and raw (sub color).

Test config bar:
- Modifiers: punctuation, numbers.
- Modes: time (15/30/60/120/custom s), words (10/25/50/100/custom), quote (all/short/medium/long/thicc), zen (no target text, ends manually), custom (user text).
- Language picker (default `english`). Theme shown in footer (default `serika dark`).

Metric formulas (`frontend/src/ts/test/events/stats.ts`, `frontend/src/ts/utils/numbers.ts`, `test-logic.ts` `buildCompletedEvent`):
- `calculateWpm(chars, seconds) = chars / 5 / (seconds / 60)`.
- Per word, `countChars(input, target, creditPartial, committed)` compares input with target char by char, where target includes its trailing space. It produces:
  - `allCorrect`: matching chars.
  - `correctWord`: chars of fully correct words only. In timed tests a correct prefix of the last word also counts.
  - `incorrect`, `extra` (typed past the end of the word), `missed` (not typed).
- **wpm** = `calculateWpm(correctWord, duration)`. Only correctly completed words count.
- **raw** = `calculateWpm(allCorrect + incorrect + extra, duration)`.
- **acc** = correct keypresses / all keypresses × 100. Counted per input event, so errors fixed later still count against it.
- **characters** stat = `correct/incorrect/extra/missed`.
- **consistency** = `kogasa(stdDev(rawPerSecond) / mean(rawPerSecond))`, where `kogasa(cov) = 100 × (1 − tanh(cov + cov³/3 + cov⁵/5))`. `stdDev` is population (÷n). `rawPerSecond` = burst history (inserted chars per 1 s bucket converted to wpm).
- Also computed: key consistency (same formula on keypress spacing), wpm consistency, AFK duration (seconds with 0 inputs).
- Chart data, per 1 s bucket:
  - `wpm`: cumulative wpm up to that second.
  - `burst`: raw speed in that second only.
  - `err`: errors in that second.
- Burst for one word = (typed length + 1 for the space) as wpm, from the word's first keypress to its last.

Invalid-result rules (`test-logic.ts`):
- Too short: duration < 1 s, time mode < 15 s, or words mode < 10 words.
- AFK: last 5 seconds have 0 keypresses.
- wpm or raw > 350 (420 for words 10).
- acc < 75%.

Settings (`/settings`) worth considering:
- behavior: difficulty (normal / expert = fail on a wrong word submitted / master = fail on any wrong key), quick restart key, blind mode, min speed / min accuracy / min word burst auto-fail, language, funbox modifiers (e.g. mirror, memory, nospace, wikipedia, zipf, ALL CAPS).
- input: freedom mode (can delete correct words), strict space, stop on error (word/letter), confidence mode (no going back / no backspace), quick end (words mode), indicate typos (below/replace/both), hide extra letters, lazy mode (strip diacritics).
- caret: smooth caret, caret style, pace caret (avg/pb/custom wpm).
- appearance: live progress / speed / accuracy / burst styles, highlight mode, typed effect, tape mode, show all lines (default 3 visible lines), speed unit (wpm/cpm/wps/cps/wph), font family/size.
- theme: flip test colors, colorful mode, presets, custom theme, random theme.
- sound: click / error sounds, time warning.

Data formats:
- Word lists: `frontend/static/languages/<name>.json` = `{ "name", "orderedByFrequency", "words": [...] }`. English variants: `english` (200), `english_1k`/`5k`/`10k`/`25k`/`450k`, `english_commonly_misspelled`, `english_contractions`, `english_doubleletter`, `english_legal`, `english_medical`, `english_old`, `english_shakespearean`.

## Text quality and animation (verified in game, 26.3)
- **Anti-aliasing:** the font atlas sampler is NEAREST and quads are scaled by `guiScale / oversample`, which gave uneven stroke weights. `core/text.fsh` (override, both versions) box-filters marked HUD glyphs by hand (`texelFetch` + `dFdx/dFdy` footprint, exact area average). Only when the pixel footprint is >= `MIN_FILTER_FOOTPRINT` (0.9 texel): magnified glyphs (the stretched background square, the 1 px caret) must stay nearest, or the background edges fade and the world shows through. `mono` uses `oversample` 8, so the filter covers GUI scales up to 8 (the window maxes out at 4 for 1048 px height).
- **Marker bits:** plain marks are `R & 15 == 3` (R bit 3 clear, error <= 12/255). The caret adds `R & 8` (caret), `G & 4` (animate), `B & 4` (came from the left); see `UiFont.markCaret`.
- **Caret slide:** one column steps on the same line are flagged (`CaretMove`, `CaretTracker`, 700 ms). `text.vsh` `hudCaretOffset` moves the caret by `6 * (1 - easeOutCubic(t))` GU, `t = GameTime * 24000 / 3` ticks. The server resets the client game time to 0 on each such move (`Stopwatch`, `SetTimePacket(0, {})`); the client then counts up, so `Globals.GameTime` (smooth per frame, partial ticks included) is "time since the last key". Verified: `mc.level.getGameTime()` resets to ~0 on a key. The instance sends no periodic time packets (only on setTime/rate/pause), so nothing else disturbs it. Do not use world time for anything else.
- **Slow-motion check:** to see a 150 ms animation, temporarily build with `HUD_CARET_TICKS = 100` and a long flag (`CaretTracker.DEFAULT_FLAG_NANOS`), type a char and screenshot (the first screenshot catches the caret at the old column).
- **Not animated yet:** char color fades, line scroll. Needs a second per-event channel (all 16 element ids are used).

## Logo and server brand (built, unit tested, verified in game, 26.3)
- `ui/Logo.kt`: one 8 x 8 grid (a tile with a block letter B) that produces everything: `pixels(theme)` for the HUD, `svg`, `banner` and `png` for the files in `assets/` (`logo.svg`, `banner.svg`, `logo.png`, used by the readme) and the server list icon. `LogoTest` fails when the checked-in files differ from the generator, so after changing the grid or the default theme regenerate them (a script that mirrors `Logo.kt` was used; the test shows the expected output).
- In game the logo is drawn like a player's face (`FaceArt`, 24 GU square, `UiFont.FACE_PIXEL` = 3, shared with the profile face) at the top left of the typing screen, in element `CONFIG` next to the centered config bar, in the player's theme colors.
- `ServerBrand.install()` (called in `BlockyType.main`): brand name `BlockyType` (F3 screen, console banner) and, in the server list, a motd plus the 64 x 64 logo icon through `ServerListPingEvent`.
